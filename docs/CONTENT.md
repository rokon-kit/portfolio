## 2. Content Principles & Ground Rules

1. **Absolute Authenticity:**
   - Never fabricate roles, metrics, performance claims, awards, or clients.
   - Use only verified career history, actual projects built, and genuine engineering capabilities.
2. **Confidentiality & Privacy:**
   - Never expose internal corporate repository names, proprietary API endpoints, private customer data, infrastructure connection strings, or non-public metrics.
   - Focus on architectural patterns, technical solutions, and open-source or sanitized case studies.
3. **The "Human" Angle in Every Narrative:**
   - Rather than just listing tech stacks ("Built with React and Node.js"), frame each feature around:
     - **The Human Challenge:** What frustration or barrier did users or the engineering team encounter?
     - **The Technical Solution:** What architecture was designed to resolve it cleanly and sustainably?
     - **The Real-World Impact:** How did the solution improve daily workflow, speed up delivery, or delight users?

### C. Featured Works & Case Studies Framework
Every featured case study must follow this editorial structure:
1. **Overview & Metadata:** Role, timeline, tech stack, and live/demo links.
2. **The Problem Space:** The challenge or opportunity in clear, relatable terms.
3. **Architecture & Engineering:** Technical decisions, trade-offs, and implementation details.
4. **Interactive or Visual Highlight:** Visual architecture diagram, code insight, or live component preview.
5. **Human Impact & Reflection:** Concrete outcome and lessons carried forward.
